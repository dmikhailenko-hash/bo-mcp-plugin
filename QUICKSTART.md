# Быстрый старт

Пять шагов, около десяти минут. Подробности — в [README](README.md).

Плагин работает локально на вашей машине: ничего не хостится, вы подключаетесь
к бэк-офису под своим логином.

## Что нужно заранее

- **Claude Code**
- **Python 3.9 или новее** в `PATH` — проверить: `python --version`
  (на macOS и Linux `python3 --version`). Ставить пакеты не нужно,
  сервер использует только стандартную библиотеку.
- Сетевой доступ к вашему BO-серверу — если он внутренний, включите VPN
- Своя учётная запись в бэк-офисе

## 1. Скачать

```bash
git clone https://github.com/dmikhailenko-hash/bo-mcp-plugin.git
cd bo-mcp-plugin
```

## 2. Настроить

```bash
python server/configure.py
```

Скрипт задаст три вопроса:

- **Адрес сервера.** Можно вставить ссылку на страницу Swagger — лишнее
  отрежется само. Enter — использовать демо-стенд.
- **Логин** — свой, не общий: все запросы идут от вашего имени, так что права
  и журнал аудита остаются персональными.
- **Пароль** — не отображается при вводе.

Подключение проверяется сразу. Если логин не принят, скрипт объяснит причину
словами. Ответы сохраняются в `.env`, он в `.gitignore` и никуда не уходит.

## 3. Подключить к Claude Code

```bash
python server/setup_check.py
```

Скрипт проверит всё по шагам и в конце напечатает готовый блок — скопируйте его
в `.mcp.json` в корне вашего проекта:

```json
{
  "mcpServers": {
    "traderevolution-bo": {
      "type": "stdio",
      "command": "python",
      "args": ["C:/путь/к/bo-mcp-plugin/server/bo_mcp_server.py"]
    }
  }
}
```

Чтобы плагин был доступен во всех проектах, положите тот же блок в
`mcpServers` в файле `~/.claude/settings.json`.

Пути пишите через прямой слэш даже в Windows. На macOS и Linux в `command`
укажите `python3`.

## 4. Установить навык

```bash
python server/install_skill.py
```

Без него тулы работают, но Claude не будет знать, в каком порядке ими
пользоваться и о чём предупреждать. Повторяйте после каждого `git pull`.

## 5. Перезапустить Claude Code

Обязательно: конфигурация MCP и файл `.env` читаются только при старте.

После перезапуска проверьте, что в `/mcp` появился `traderevolution-bo`.

## Как убедиться, что всё работает

Проверок две, и они независимы. Первая смотрит на вашу машину, вторая — на то,
что Claude Code на самом деле загрузил. Они могут расходиться, и почти всегда
причина в том, что после изменений не перезапустили Claude Code.

### Проверка 1 — машина

```bash
python server/setup_check.py
```

Все строки должны быть `OK`:

```
[  OK  ] Python 3.13.5
[  OK  ] Configuration file: ...\.env
[  OK  ] Skill installed: ...\.claude\skills\traderevolution-bo
[  OK  ] Base URL: https://ваш-сервер/proftrading/rest
[  OK  ] Credentials present (login: ваш_логин)
[  OK  ] TCP connection to ваш-сервер:8443
[  OK  ] Authenticated as ваш_логин
[  OK  ] Swagger specification: 634 operations
[  OK  ] Report catalogue: 95/96 reports, 58 column functions
[  OK  ] Reports surfaced: 84 of 96, 12 hidden as clutter
```

`WARN` — не ошибка: плагин работает, но чего-то не хватает, и строка объяснит,
чего именно. `FAIL` нужно устранить.

### Проверка 2 — сам Claude Code

Попросите Claude:

> Run bo_status

Смотрите на три вещи в ответе:

| Поле | Должно быть |
|---|---|
| `credentialsConfigured` | `true` |
| `spec.operations` | `634` |
| `reportCatalog.reports` | число отчётов на вашем стенде |

**Если блока `reportCatalog` нет вообще — Claude Code работает на старой
сборке.** Перезапустите его: конфигурация MCP читается только при старте.
Это же касается любых правок в `.env`.

Строка `auth.state: "not authenticated"` сразу после запуска — нормально:
сервер логинится лениво, при первом реальном запросе.

### Проверка 3 — сквозная

Три вопроса подряд, каждый проверяет свой слой:

> что показывает Trades Report и что значат его колонки

Отвечает из локального каталога, без обращения к серверу. Если ответ есть —
работают каталог и навык.

> найди эндпоинт для списка счетов

Ищет по спецификации. Если находит — загружен Swagger.

> покажи комиссии за последние сутки

Реальный запрос к BO. Если пришли данные — работает авторизация и сеть.

### Проверка 4 — что защита на месте

> создай операцию по счёту на 100 долларов

Должен прийти отказ: сервер работает только на чтение, и запрос не покидает
вашу машину. Если операция выполнилась — у вас включена запись, проверьте
`TR_BO_ALLOW_WRITES` в `.env`.

## Если у вас свой BO, а не демо-стенд

Соберите каталог отчётов своей инсталляции — это займёт пару минут:

```bash
python server/build_report_catalog.py
```

В репозитории лежит каталог демо-стенда. Идентификаторы и названия отчётов у
разных инсталляций различаются, поэтому без пересборки Claude предупредит, что
каталог чужой.

## Если что-то не работает

Сначала запустите `python server/setup_check.py` — он проверяет всё
по очереди и объясняет, что именно не так.

| Симптом | Причина |
|---|---|
| `traderevolution-bo` нет в `/mcp` | Python не в `PATH`, либо не перезапустили Claude Code |
| «No credentials found» | `.env` читается один раз при старте — перезапустите Claude Code |
| «Cannot reach …» | Неверный адрес, нет VPN, или самоподписанный сертификат — тогда `TR_BO_INSECURE_TLS=true` в `.env` |
| Вход отклонён | Код `1.2.0.11` — неверный логин или пароль; `2.0.2.4` — у учётной записи нет доступа к REST API, нужен администратор |
| `catalogWarning` в ответе | Каталог собран для другой инсталляции — выполните шаг про `build_report_catalog.py` |

## Что плагин не сделает

По умолчанию доступ **только на чтение**: `POST`, `PUT`, `PATCH` и `DELETE`
отклоняются, не выходя из вашей машины. Отдельно заблокированы операции с
деньгами, удаление пользователей и счетов, сброс паролей — даже если запись
включена.

Оба ограничения снимаются только вручную в вашем `.env` и только осознанно.
